2. 重要な設計判断（変えるときは仕様の優先順位を確認）
  - 金額・状態の正本は PostgreSQL。業務の書込は SECURITY DEFINER 関数のみ（API ロールにテーブル書込権限なし）。
  - 券 token は DB に渡さない（サーバーで HMAC → digest 照合）。印刷データは AES-256-GCM で private storage、取得は POST 本文で返す（URLに出さない）。
  - 「取得URL有効60秒」: 印刷データは URL を発行せず、権限・MFA・監査付き POST の応答本文で返すため URL 自体が存在しない。
    添付・組織データ出力は 60 秒の署名 URL。
  - GET /operations/{id} は ID か idempotency key で照会。未記録は "pending"（同じ key で再送しても二重にならない）。
  - 状態の追加: 精算行に held/resolved/failed、取消に requested/approved/rejected を持たせた（仕様の状態列挙はバッチ側を厳守）。
  - 事業の「公開申請」は status=draft のまま submitted_at を立てる（仕様の draft/active/suspended/closed を維持）。
  - 未承認の精算案の「破棄」は行ごと削除（金銭確定前で、sources を解放するため）。監査に破棄前の内容を記録。
  - 取消が却下された受付は、同じ受付で再申請できない（reversals.redemption_id 一意）。必要なら事務局が相談で対応。
  - フォーム: 口座変更は React Hook Form + 共有 Zod スキーマ。他のフォームは制御コンポーネント＋サーバー側 Zod（全 API で再検証）。
    RHF へ揃える場合は src/components/merchant/BankChangeForm.tsx を手本に。
  - Next 16 では middleware が proxy.ts に改称（src/proxy.ts）。CSP nonce はここで付与。
